# Getting started

This guide is for a separate NeoForge add-on mod that depends on IC2 Refactored. It does not require copying IC2R source into the add-on.

## Requirements

- Minecraft `1.21.1`
- NeoForge, matching the version expected by the IC2R build you target
- Java 21
- A development environment using Gradle
- IC2 Refactored as a development/runtime dependency

The inspected source snapshot uses NeoForge `21.1.234` and Java toolchain 21. Version values can change; check the target IC2R revision before setting up your dependency.

## Set up the add-on project

Create a normal NeoForge mod project and give it its own unique mod ID, for example `example_ic2_addon`. Keep your Java package, registry namespace, resource folders, and `neoforge.mods.toml` metadata consistent with that ID.

Add IC2R as a dependency using the distribution or Maven coordinates available for the specific release you target. The repository contains a Maven publishing configuration, but the exact published artifact coordinates depend on how that build has been published. Do not assume an artifact is available just because the build contains a `maven-publish` block.

In `META-INF/neoforge.mods.toml`, declare a dependency on mod ID `ic2` and constrain it to the versions your add-on actually supports. Follow the dependency syntax generated by your NeoForge MDK.

## Build and test

From your add-on project on Windows:

```powershell
.\gradlew.bat build
.\gradlew.bat runClient
```

On Linux or macOS, use `./gradlew build` and `./gradlew runClient`.

Test in a development instance containing the same IC2R version that you declared as a dependency. A successful Java compile alone does not prove that registries, block entity types, assets, or energy behavior work in-game.
